p5.strands gotchas

Things that bit us while building the sketches in this project. Not exhaustive — just the ones with a clear symptom and a clear workaround.

1. finalColor.set(node) emits a hook with no return

Symptom Shader fails to compile with ERROR: 'HOOK_getFinalColor' : Function does not return a value.

Passing a single strand node (e.g. a uniformVec4) directly to finalColor.set emits a hook body that mentions the value but never returns it.

Fix Unpack into an array literal — strands constructs a fresh vec4 and emits the return correctly.

// Broken
finalColor.set(oc);

// Works
finalColor.set([oc.x, oc.y, oc.z, oc.w]);

2. scalar * node multiplication fails at runtime

Symptom TypeError: X.mult is not a function where X is a plain JS number.

The strands transpiler rewrites a * b as a.mult(b). If the left operand is a plain JS number (not a strand node), it has no .mult and the shader throws.

Fix Put the strand node first. 0.35 * inv → inv * 0.35.

3. Unused uniforms are silently tree-shaken

Symptom setUniform("name", value) seems to do nothing. The shader runs but ignores your value.

If you declare uniformVec4("name") but never reference the returned node in your hook, strands omits the uniform vec4 name; from the compiled GLSL. setUniform then silently fails to find a binding.

Fix Make sure the node is actually used somewhere in your hook (e.g. in finalColor.set([oc.x, oc.y, oc.z, oc.w])). To verify, console.log(myShader.fragSrc()) and search for the uniform declaration.

4. pixelInputs has no position

Symptom pixelInputs.position reads as undefined or compiles to garbage; can't get the surface point in the fragment stage.

The fragment-stage Inputs struct (in phong.frag) only contains normal, texCoord, color, plus lighting and material slots — no position.

Fix Capture the view-space position in cameraInputs and pass it down with a sharedVec3.

let viewPos = sharedVec3();

cameraInputs.begin();
viewPos = cameraInputs.position;
cameraInputs.end();

finalColor.begin();
// ... use viewPos.x / .y / .z
finalColor.end();

5. finalColor.texCoord documented but doesn't work in JS

Symptom Reading finalColor.texCoord from inside the block returns undefined; UV-driven effects in finalColor can't see the surface's UV.

The underlying GLSL hook signature is HOOK_getFinalColor(vec4 color, vec2 texCoord), but the JS block-form getter for texCoord wasn't wired up at the time we tried it.

Fix Capture pixelInputs.texCoord into a sharedVec2 and read it from finalColor.

6. box() has per-face normals — normal-push tears it apart

Symptom A breathe / normal-push / constant-width-outline shader produces disjointed floating quads instead of an inflated mesh.

p5's box() stores per-face normals (each of the 6 faces has its own outward normal). When you displace each vertex along its normal, adjacent faces push in different directions and the mesh separates at the seams.

Fix Test normal-based effects on sphere() or torus(), which have welded, smoothly-interpolated normals. There's no clean fix for box() short of switching to a uniform-scale inflation.

7. Built-in primitives are unit-sized in objectInputs

Symptom A vertex-displacement shader designed around real dimensions (e.g. position.y * 0.02 for a 320-unit-tall box) does nothing visible.

p5 builds box() / cylinder() / cone() / sphere() at unit size and applies your dimensions via the model matrix afterwards. So inside objectInputs, position components are in [-0.5, 0.5] regardless of what you passed to the primitive.

Fix Either (a) scale your factor up to match unit space (e.g. * 5 in twist), or (b) switch to worldInputs, whose position is post-model-matrix and so in real-world units.

8. Whole-vector += on inputs.position is a no-op

Symptom cameraInputs.position += someVec3 compiles but doesn't displace anything.

Only the component-wise mutations from the docs (position.x += ..., etc.) reliably round-trip. We couldn't get the whole-vector form to work.

Fix Write each component separately.

// Broken (silent)
cameraInputs.position += normal * amount;

// Works
cameraInputs.position.x += normal.x * amount;
cameraInputs.position.y += normal.y * amount;
cameraInputs.position.z += normal.z * amount;
